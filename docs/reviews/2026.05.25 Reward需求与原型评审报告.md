# PRD 评审报告

> 评审时间：2026-05-25  
> 评审对象：Reward 家庭愿望契约系统 PRD v2.1、18 个产品设计问题归档、HTML 原型、MVP 页面规格与验收口径  
> 评审方式：已收到 PRD 和原型，按联合评审处理。  
> 使用标准：prd-review-gate 深度需求 + 原型评审标准

## 1. 需求理解摘要

- 业务目标：帮助家庭围绕“孩子的愿望”和“可被履约的小承诺”建立低冲突、可兑现、可留念的家庭契约闭环。
- 目标用户：孩子、签约家长、共同签约家长、轻量见证人；平台仅作为记录、提醒、归档和边界保护方。
- 核心场景：家长建立奖励池，孩子发起愿望，双方确认契约，孩子完成行动并提交证据，家长回应并兑现，系统生成温暖记忆。
- 主要能力：家庭与角色、契约状态机、愿望与奖励池、番茄钟与任务记录、证据提交、家长回应、延期与修复、见证人、记忆后院、AI 文案辅助、数据与隐私边界。
- 范围：MVP 聚焦单家庭、单孩子、一个小愿望契约的完整闭环；明确排除学校管理、支付托管、开放社交、排行榜、抽卡、强监控和复杂商业化。
- 预期结果：MVP 能在电脑端演示完整家庭闭环，并为后续真实试点保留权限、隐私、安全和可审计基础。

## 2. 评审结论

- 结论：有条件通过
- 需求类型：完整需求评审
- 输入物情况：PRD + 原型
- 总体判断：需求方向清晰，产品边界克制，PRD 对核心闭环、角色权限、反控制原则和 MVP 范围的表达较完整；HTML 原型能证明产品气质、信息架构和核心体验方向。但原型仍偏“概念与信息架构原型”，对 P01-P10 的完整交互、异常态、权限态、状态流转和测试可执行细节覆盖不足。建议允许继续推进 MVP 开发与设计细化，但在进入多人协作开发和真实家庭试点前，必须补齐下方 P1/P2 项。
- 问题汇总：P0 = 0 / P1 = 2 / P2 = 5 / P3 = 3 / P4 = 2
- 是否触发一票否决：否
- 是否可进入开发评审：是，但仅限 MVP 范围；P1 项需要在正式多人开发前关闭。
- 是否可进入设计细化：是。
- 是否可进入测试准备：是，但需要同步补齐状态、权限、异常和隐私测试用例。

## 3. PRD 与原型一致性检查

整体一致性较高：

- 产品定位一致：PRD 与原型都强调“家庭愿望契约”，不是学习监督、学校管理、任务打卡或付费托管工具。
- 核心闭环一致：奖励池、孩子愿望、契约确认、完成证据、家长回应、记忆归档在 PRD 与原型中均存在。
- 角色边界一致：孩子、家长、见证人都被定义为不同视角；见证人被限制为“见证与提醒”，不是裁判。
- 情绪调性一致：原型采用猫咪后院、纸卡、温暖低刺激表达，符合 PRD 中反攀比、反控制、反游戏化的原则。
- MVP 页面范围基本一致：PRD 的 P01-P10 与原型说明中的 MVP 十页方向一致。

主要不一致或不足：

- PRD 的状态机和权限细节显著强于原型，原型尚未充分展示延期、修复、见证、证据隐私和异常处理。
- PRD 提到的儿童邀请、家庭绑定、共同签约、见证链接等身份流程，在原型中仍偏概念展示。
- PRD 中 AI、数据安全、审计和未成年人保护要求较重，但原型没有把这些后台约束转化为足够明确的页面反馈、禁用态、拦截态和提示文案。

## 5. 风险提示

- 最大产品风险不是“功能不够”，而是家庭冲突场景下的边界表达不够清楚。尤其是延期、未回应、修复和见证提醒，必须避免让系统看起来像裁判或惩罚工具。
- 最大研发风险是状态机、权限矩阵、页面交互和审计日志各自为政。建议把 domain 层状态机作为唯一真相，并让页面、API、测试和文档都引用同一套状态事件。
- 最大合规风险来自未成年人数据，尤其是照片证据、孩子私密表达、AI 文案输入和试点家庭数据保留。MVP 内部演示可以 mock，但真实试点必须补齐告知与处理流程。
- 最大原型风险是视觉氛围很好，但还不足以覆盖工程需要。温暖的猫咪后院方向应保留，同时要补齐低层交互细节。

## 6. 通过前必须补齐项

建议将以下内容作为“有条件通过”的关闭条件：

1. 补齐 P01-P10 页面状态表：默认、空态、加载、错误、提交中、禁用、无权限。
2. 输出唯一状态机映射表：业务中文状态、代码枚举、触发事件、角色权限、审计事件。
3. 明确 MVP 身份方案：真实登录还是 mock role switcher；儿童邀请码如何创建、使用、过期和防误入。
4. 明确证据照片 MVP 规则：mock/真实上传、允许内容、敏感内容提示、删除与封存。
5. 明确 AI/Kimi MVP 策略：默认 mock 或模板；真实接入前必须脱敏、可关闭、失败降级。
6. 补齐 P09/P10 的延期、修复、见证提醒分支交互。
7. 补齐奖励池字段级校验与禁用奖励文案。

## 7. 评审方最终结论

本次 PRD + 原型联合评审结论为：有条件通过。

理由如下：

- PRD 的产品判断成熟，核心边界清楚，MVP 范围基本合理。
- 原型准确表达了产品气质、角色关系、核心闭环和猫咪后院式的低压力体验。
- 当前材料已经可以支撑 MVP 继续开发，也可以支撑内部电脑端 Demo。
- 但当前原型和部分产品规则尚不足以直接支撑多人并行开发、完整测试设计和真实家庭试点。

建议下一步不是扩大功能，而是把已有范围“压实”：状态机、权限、页面状态、隐私规则、AI 边界和分支交互先定住，再继续做体验打磨。
