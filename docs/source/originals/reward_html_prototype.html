01 / POSITION

产品到底服务谁？

对外帮家长减少反复拉扯，对内保护孩子努力；真正修复的是家庭承诺系统。

家长

付费对象

买到的不是“审判自己”，而是少催促、少争吵、奖励不乱给、孩子更主动。

孩子

情感对象

获得愿望被认真对待、规则不被随便修改、努力不会被否认的确定感。

家庭

价值对象

最终不是让某一方赢，而是让家庭规则更稳定，承诺系统更可信。

02 / CORE LOOP

首个小约定闭环

MVP 只验证一个核心闭环：创建约定、孩子守约、家长回应、生成记忆。

1家长建家庭确认 5 条原则，完成奖池初始化。
2孩子选愿望从家庭小愿望池里选，不自由开价。
3生成契约目标、奖励、证据、兑现时间全部写清。
4开始守约25 分钟愿望番茄钟 + 一句话复盘。
5家长回应已兑现、延期或约定复盘，不能无声关闭。
6进入记忆生成亲子日记，愿望后院出现猫猫。
03 / APP PROTOTYPE

四个核心端体验

用四组原型屏呈现产品的整体规划：家长端、孩子端、见证人、约定修复。

家长端首页

今天不用催 3 次

周末科技馆孩子已完成 3/5 个专注时段
待回应“整理书桌”已完成，建议今晚兑现小奖励。
奖池健康度小愿望偏物质，建议增加陪伴/自主权奖励。

家长真正买到什么

  • 目标和奖励不再拍脑袋。
  • 少催促，孩子主动开始守约。
  • 完成后系统提醒兑现，减少反悔和遗忘。
  • 通过奖池避免奖励通胀。

关键页面

  • 家庭契约原则确认。
  • 小/中/大/梦想奖池初始化。
  • 创建约定：目标、奖励、证据、兑现时间。
  • 兑现提醒与亲子留言。
孩子端 · 愿望后院

不是任务表，是我的小院

愿望：周末科技馆再完成 2 个专注，愿望树会开花。
今天的安静猫它喜欢认真开始的人。

孩子为什么愿意用

  • 愿望被认真记录。
  • 努力会改变自己的愿望后院。
  • 猫猫、徽章、纪念册不是抽卡，而是努力痕迹。
  • 树洞默认属于自己。

防沉迷原则

  • 不排行榜、不连续登录惩罚。
  • 不无限刷新、不抽卡。
  • 每日互动有限，完成后提示离开。
  • 分享只展示努力世界，不展示奖励金额。
见证人 H5

只见证，不判案

你被邀请见证小安正在为“周末科技馆”努力。
权限：纪念见证人可看完成纪念，不看金额、证据、争议、树洞。

见证人分级

  • 纪念见证人：看成功和纪念。
  • 提醒见证人：温和提醒回应。
  • 协商见证人：双方授权后进入。
  • 裁定见证人：默认关闭。

为什么要弱权限

见证人是承诺稳定器，不是家庭法官。权限过重会把亲属变成审判团。

约定修复中心

这个愿望需要商量一下

原始规则完成 5 次专注，周六去科技馆。
当前分歧已完成 4 次，孩子希望部分折算。
AI 建议可折算为 4 个小愿望点，或补做 1 次后兑现。

产品不做裁判

  • 展示原始契约。
  • 整理双方理由。
  • 识别事后加码。
  • 提供延期、补证、补做、折算、封存。

争议不等于努力归零

已完成部分可以先确认，争议部分进入协商。孩子也可以放弃奖励，但保留努力记录。

05 / BOUNDARY

必须写进产品底层的边界

这些边界决定产品是不是可信，而不是可有可无的“合规补丁”。

不做原因替代方案
学校 / 机构路径会变成管理、排名、续费和获客工具。长期只做家庭端。
视频监督 / 默认强锁控制感强，孩子会把产品视为敌人。孩子主动开始守约，轻证据记录。
支付托管 / 奖励钱包资金池、退款、未成年人支付风险高。只做订阅、承诺记录、兑现提醒。
商家导购 / 商品抽佣会破坏家长对推荐动机的信任。只从家庭用户侧订阅收费。
抽卡式惊喜容易变成盲盒刺激。愿望星星、进度式惊喜、三选一。
同校/班级数据池重识别和攀比风险高。家长端大样本低攀比灵感库。

07 / REVIEW

你看原型时重点判断

这份原型不是最终 UI，而是用来验证整体方向是否符合我们讨论的产品灵魂。

需要确认

  • 家长端是否足够像“帮我省心”，而不是“审判我”。
  • 孩子端是否足够像“我的愿望世界”，而不是“爸妈的任务表”。
  • MVP 是否够轻，但没有丢掉契约、履约、记忆三件事。
  • 见证人和修复中心是否足够温和。

暂时不确认

  • 猫猫美术风格不是最终稿，只代表轻治愈方向。
  • 页面布局不是最终交互，仅用于看信息架构。
  • 奖池算法和 AI 规则还需要单独做产品原型。
  • 品牌名 Reward 可继续调整。
