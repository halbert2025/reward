## 1. 原型定位

- 原型主题：Reward 家庭愿望契约系统。
- 对外表达：把随口承诺，变成孩子相信的家庭约定。
- 产品人格：家庭契约教练、温柔史官、愿望后院。
- 核心区别：不是控制软件、不是家庭法官、不是奖励商城。

## 4. 核心端体验

### 家长端

- 体验关键词：少催促、少争吵、奖励不乱给、孩子更主动。
- 关键内容：家庭契约原则确认、奖池初始化、创建约定、兑现提醒、亲子留言。
- 文案方向：帮助家长省心，不审判家长。

### 孩子端

- 体验关键词：不是任务表，是我的愿望后院。
- 关键内容：当前愿望卡片、愿望番茄钟、猫猫来访、纪念卡、树洞预留。
- 文案方向：努力被记录，愿望世界被点亮。

### 见证人端

- 体验关键词：只见证，不判案。
- 默认权限：只看契约摘要和完成纪念，不看金额、证据、争议、树洞。
- MVP：只保留 1 个免费纪念见证人占位。

### 约定修复

- 体验关键词：这个愿望需要商量一下。
- 产品原则：展示原始契约、整理双方理由、提供补证/补做/延期/折算/封存方案，不做裁判。
- MVP：不做完整修复中心，但家长回应中保留“待复盘”路径。

## 5. 关键交互

- 查看核心原型
- 看 MVP 范围
- 开始守约
- 开始 25 分钟守约
- 送一句祝福
- 家长端 / 孩子端 / 见证人端 / 约定修复 标签切换

## 6. 视觉方向

- 气质：暖萌治愈、低刺激、纸感手账。
- 主色：米白背景、柔和绿色、金色点缀、低饱和辅助色。
- 组件：圆角卡片、轻阴影、柔和进度条、手机框预览、线框页面卡。
- 孩子端视觉：愿望后院、猫猫、小院、愿望能量。
- 避免：强红点、排行榜、抽卡语言、赛博炫光、商业手游式高刺激 UI。

## 7. 产品边界在原型中的呈现

- 不做学校 / 机构路径。
- 不做视频监督 / 默认强锁。
- 不做支付托管 / 奖励钱包。
- 不做商家导购 / 商品抽佣。
- 不做抽卡式惊喜。
- 不做同校 / 班级数据池。
- 见证人弱权限。
- 树洞默认私密，后续需在权限矩阵中落实。

## 8. 后续研发使用建议

- 前端实现不要直接照搬 HTML 原型结构，应先生成 docs/design/screen-spec.md。
- 原型中的猫猫只是方向，不是最终美术资产。
- 原型中的页面布局用于信息架构验证，不代表最终交互细节。
- MVP 首屏应优先服务可用闭环，而不是营销落地页。
