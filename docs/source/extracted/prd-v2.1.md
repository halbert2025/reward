### 2. 执行摘要

“让孩子的努力不被看不见，让家长的承诺不被说散。”

Reward 是一款面向家庭端的亲子愿望契约产品，核心目标是把家庭中的口头承诺转化为结构化、可执行、可记录、可提醒、可修复、可归档的家庭约定。产品帮助家长减少催促和扯皮，帮助孩子把愿望转化为主动努力，并把完成过程沉淀为成长记录。

| 项目 | 完整定义 |
| --- | --- |
| 一句话定位 | 把随口承诺，变成孩子相信的家庭约定。 |
| 产品本质 | 家庭契约系统 + 愿望驱动系统 + 轻证据系统 + 成长记录系统。 |
| 不是 | 不是家长控制软件，不是学校管理工具，不是奖励商城，不是支付托管，不是儿童社交平台。 |
| 首批用户 | 8-12 岁孩子家庭；家长愿意讲规则、愿意兑现承诺，但缺少目标奖励匹配和执行工具。 |
| 核心闭环 | 家长配置奖池 → 孩子选择愿望 → 创建约定 → 孩子主动守约 → 轻证据记录 → 家长兑现 → 亲子日记和愿望后院变化。 |
| 产品灵魂 | 规则前置、孩子主动、努力可见、家长履约、争议可修复、记忆可保存。 |
| MVP 验证 | 首个小约定是否能完整跑通，家庭是否愿意创建第二个约定。 |
| 长期壁垒 | 家庭汇率模型、能力归档、孩子愿望世界、长期成长档案、匿名低攀比灵感库。 |

### 3. 产品背景与核心洞察

### 3.1 家庭奖励的真实矛盾

家庭教育中，家长常用奖励激发孩子行动，但传统口头奖励存在四个结构性问题：奖励是否合理不清楚、目标是否可验收不清楚、家长是否会兑现不确定、孩子长期是否会变成奖励依赖不确定。

| 冲突 | 表现 | 产品机会 |
| --- | --- | --- |
| 承诺不稳定 | 家长一开始答应，验收时提高标准或延期兑现。 | 原始契约留痕、兑现提醒、约定修复。 |
| 目标不量化 | “表现好”“认真学习”难以验收。 | AI/规则帮助把目标改成可执行、可证据化任务。 |
| 奖励不匹配 | 小任务换大愿望，或大挑战只给轻奖励。 | 家庭奖池与目标难度匹配，建立家庭汇率。 |
| 监督不可信 | 番茄钟只能证明没玩手机，无法证明质量。 | 轻证据体系：时间型、结果型、质量型分开。 |
| 长期依赖 | 孩子把学习、家务和生活责任都价格化。 | 任务分层、积分衰减、能力退役、归档仪式。 |

### 3.2 与现有工具的差异

| 已有方式 | 问题 | Reward 差异 |
| --- | --- | --- |
| 微信 | 有聊天记录但无结构、无状态、无验收。 | 契约字段化、状态机化、可归档。 |
| 纸质表 | 能打卡但容易忘、容易改、无长期记忆。 | 轻证据、亲子日记、年度报告。 |
| 番茄钟 | 只计时，不解决奖励、兑现和争议。 | 愿望番茄钟绑定契约和兑现提醒。 |
| 家长控制 App | 单向控制，容易让孩子抵触。 | 孩子主动守约，家长也承担履约责任。 |
| 家务奖励 App | 偏单向任务/零花钱，家长履约不是核心。 | 双向承诺，家长兑现也进入流水。 |

### 4. 产品定位、品牌语言与产品人格

### 4.1 产品人格

| 人格 | 含义 | 产品表现 |
| --- | --- | --- |
| 史官 | 如实记录原始契约、完成过程和兑现状态。 | 不可篡改的契约版本、履约流水、日记。 |
| 主持人 | 让双方按流程表达，不做裁判。 | 约定修复中心、AI 表达转译。 |

| 孩子努力保护者 | 保护孩子已经付出的努力不被抹掉。 | 封存、长期保存、成长档案。 |
| 愿望世界建设者 | 让孩子感觉努力会让自己的世界生长。 | 愿望后院、猫猫来访、纪念卡。 |

### 4.2 对外品牌表达

对外不应强调“监督家长履约”或“控制孩子”，而应强调“少催促、少扯皮、孩子努力有记录、家长承诺有提醒”。

| 首页主卖点 |
| --- |
| • 主标题：把随口承诺，变成孩子相信的家庭约定。 |
| • 副标题：帮家长说清目标和奖励，帮孩子记录努力过程，到点提醒兑现，减少催促、反悔和扯皮。 |
| • 核心三点：定清楚、看得见、做得到。 |

### 6. 产品边界与明确不做清单

本项目的边界是品牌信任的一部分。为保护家庭信任、未成年人隐私和产品中立性，以下方向不进入路线图，或至少不进入 MVP/V1。

| 不做项 | 原因 | 替代方案 |
| --- | --- | --- |
| 学校路径 / 老师端 | 会变成教育管理工具，合规与责任复杂。 | 只做家庭端；老师不作为默认角色。 |
| 机构路径 | 机构天然有获客和续费目标，会破坏中立性。 | 不做机构版，不做课程转化。 |
| 支付托管 / 钱包 | 触碰资金池、退款和未成年人支付风险。 | 只做会员订阅、奖励承诺记录和兑现提醒。 |
| 商家导购 / 商品抽佣 | 家长会怀疑推荐动机，破坏品牌信任。 | 只从用户侧订阅收费。 |
| 视频监督 / 全天监控 | 隐私和儿童信任风险过高。 | 轻证据：番茄钟、照片、复盘、家长确认。 |
| 默认强锁手机 | 容易变成控制软件。 | 契约式专注，孩子主动开始；V2 才考虑双方同意的自愿专注护盾。 |
| 开放儿童社交 | 隐私、欺凌、审核成本过高。 | 只做展示型小院名片，后置且可关闭。 |
| 同校/班级数据池 | 小样本重识别和攀比风险高。 | 只做大样本、匿名、家长端低攀比灵感库。 |
| 抽卡式惊喜 | 未成年人概率刺激和消费诱导风险。 | 进度式惊喜，小愿望轻随机，中愿望以上靠累计。 |

### 8. 家庭契约系统

### 8.1 契约类型

| 类型 | 定义 | 示例 | 记录强度 |
| --- | --- | --- | --- |
| 轻承诺 | 非正式提醒，不进入强履约机制。 | 周末有空去公园。 | 只提醒，不记严重失信。 |
| 正式契约 | 目标、奖励、验收、兑现时间明确。 | 完成 5 次专注，周六看电影。 | 完整记录延期/兑现/复盘。 |

| 梦想愿望 | 长期且指向性努力，不可由低级任务随意替代。 | 为演唱会/旅行/长期项目建立专项计划。 | V1/V2 专项立项。 |

### 8.3 契约状态机

| 状态 | 含义 | 可执行动作 |
| --- | --- | --- |
| 草稿 | 家长或孩子正在创建。 | 编辑、删除、提交给对方确认。 |
| 待确认 | 一方发起，另一方未确认。 | 同意、修改、拒绝、AI 解释。 |
| 进行中 | 双方已确认，孩子正在执行。 | 开始守约、提交证据、中途退出说明。 |
| 已达成 | 任务已完成，进入家长回应阶段。 | 兑现、延期、复盘。 |
| 待回应 | 家长尚未确认兑现或延期。 | 提醒、请求见证人提醒、进入风险关注。 |
| 已兑现 | 奖励完成。 | 生成亲子日记、纪念卡。 |
| 已延期 | 家长说明延期原因和新时间。 | 到期再提醒。 |
| 待复盘 | 双方对完成或兑现有分歧。 | 进入约定修复中心。 |
| 已搁置 | 暂时不继续，但记录保留。 | 恢复、封存。 |
| 已封存 | 不再推进，进入时间胶囊。 | 导出、长期保存。 |

### 9. 奖池、愿望与目标-奖励匹配系统

### 9.1 家庭奖池初始化

奖池不由平台统一定价，而由家庭根据自身预算、时间和价值观初始化。平台提供结构、参考和风险提示，避免把小资样本或高消费偏好强加给不同家庭。

| 奖池 | 家庭自定义维度 | 示例 |
| --- | --- | --- |
| 小愿望 | 低金额/低时间成本，当天或短周期兑现。 | 选晚饭、多讲一个故事、10 分钟自主时间、小贴纸。 |
| 中愿望 | 需要连续 3-7 天或多个小任务累计。 | 书店自由挑选、亲子电影夜、周末活动。 |
| 大愿望 | 需要阶段性项目和多次任务。 | 短途出行、较高价值物品、课程体验。 |
| 梦想愿望 | 长期专项计划，必须指向该愿望本身。 | 演唱会、旅行、长期项目。 |

### 9.2 目标-奖励匹配规则

孩子可以表达愿望，但系统将愿望拆解为金额、时间、陪伴、稀缺性、准备成本等基础元素。

系统基于家庭奖池边界给出奖励等级建议，并说明理由。

家长可以调整目标难度或奖励等级，但需要给出理由。

孩子需要确认自己是否认可该目标难度与奖励价值。

如果孩子认为中、家长认为大，系统给出双方逻辑与妥协方案；谁妥协要被看见。

跨奖池争议说明家庭奖池初始化可能有问题，需要重新校准。

| 场景 | 系统建议 |
| --- | --- |
| 孩子想要高价值奖励 | 拆成多个阶段任务；大愿望不可由单次小任务直接获得。 |
| 孩子无欲无求 | 家长端从低攀比灵感库筛选合适愿望进入家庭奖池。 |
| 家长不知奖励值不值 | 系统展示家庭奖池边界内的类似任务-奖励参考，不给孩子看同龄数据。 |
| 孩子想合成奖励 | 小愿望可合成中愿望，中愿望可合成大愿望；梦想愿望不可替代性合成。 |

### 10. 任务、动机与能力归档系统

“奖励不是为了购买服从，而是为了帮助孩子练习自我管理。”

### 10.1 任务分类

| 类型 | 定义 | 奖励规则 |
| --- | --- | --- |
| 不可交易行为 | 安全、吃饭、睡觉、医疗、基本照顾、尊重人格等法定/伦理底线。 | 不可建模为奖励或惩罚条件。 |
| 基础责任 | 年龄段应承担的基本生活责任。 | 可记录，可轻量鼓励，不给高价值奖励。 |
| 日常任务 | 稳定执行的基础习惯。 | 基础能量，不完成可能影响其他奖励比例，但不可过度惩罚。 |
| 习惯养成 | 需要一段时间建立的行为。 | 前期奖励，后期积分衰减，成熟后退役。 |
| 挑战任务 | 超出日常能力边界的任务。 | 可绑定正式奖励。 |
| 梦想项目 | 长期愿望对应的专项努力。 | 必须指向性努力，不可随意替代。 |

### 10.2 积分衰减与能力退役

系统应避免孩子形成“没有奖励就不做”的模式。对于持续完成的任务，奖励权重逐步下降，并通过“能力归档”给予仪式性认可。

新任务期：给予明确反馈，帮助启动。

稳定期：减少物质奖励，提高自主权、陪伴和精神奖励比例。

退役期：任务进入能力库，不再作为奖励任务，但保留徽章和纪念。

复发期：如果任务长期失败，可重新从日常任务调整为奖励任务。

| 能力归档价值 |
| --- |
| • 能力归档不是小功能，而是对孩子的肯定：“我相信你已经可以做好这件事。” |
| • 它把外部奖励转化为自我效能感，是从奖励走向自驱的关键设计。 |

### 11. 轻证据与专注系统

### 11.1 番茄钟到底证明什么

番茄钟不能证明孩子学会了、写对了或完成质量高。它只能证明在约定时间内孩子进行了一个“开始守约”的仪式，并至少没有明显使用本设备进行干扰活动。因此产品应将番茄钟定位为努力过程证明，而不是任务质量证明。

| 任务类型 | 证据方式 | 通过规则 |
| --- | --- | --- |
| 时间型 | 愿望番茄钟 + 一句话复盘 | 可自动达成，家长可事后提出异议。 |
| 结果型 | 完成后照片 / 文件 / 勾选清单 | 家长确认或默认通过。 |
| 质量型 | 复盘、抽查、家长评价、必要时见证人意见 | 需事前写明质量标准。 |
| 长期型 | 阶段进度 + 多次证据 + 宽限次数 | 可补做、补证、折算。 |

### 11.2 专注系统原则

默认不做强锁手机，不做视频监督。

孩子主动点击“开始守约”。

中途退出需要写原因，退出不是惩罚，而是本轮未完成。

家长看到趋势和结果，不看实时监控。

强锁只作为 V2 高级可选项，且需双方同意。

手表和设备接入后置，用于轻量运动、提醒和低侵入记录。

### 11.3 假照片与证据异议

| 场景 | 规则 |
| --- | --- |
| 小任务疑似假证据 | 家长可提出异议；孩子可补交；严重时本次小任务作废。 |
| 中任务疑似假证据 | 允许多次证据提交，造假次数低于拖延宽限次数，避免孩子被迫造假。 |
| 家长主观否定 | 如果验收标准未事前写明，不允许事后加码；进入约定修复。 |
| 证据采集过重 | 任务创建时由双方确认最低证据要求；AI 可辅助设计轻证据。 |

### 12. 家长履约、失信与退出机制

平台不能强制家长履约，但可以拒绝继续让孩子为不可信的承诺努力。MVP 阶段不突出失信惩罚，但后台应记录履约状态；V1 后进入正式分级机制。

| 情况 | 处理 |
| --- | --- |
| 正当延期 | 允许延期，但必须说明原因和新兑现时间，不算严重失信。 |
| 未回应 | 24 小时待回应，72 小时履约关注，7 天可记中度失信。 |
| 单方加码 | 严重风险：新要求只能进入下一份契约，不能影响本次兑现。 |
| 奖励缩水 | 孩子同意则协商调整；不同意则视为未完整兑现。 |
| 明确拒绝兑现 | 严重失信，进入修复或受限机制。 |
| 篡改记录 | 严重失信，破坏史官根本。 |

### 12.1 状态分级

| 阶段 | 触发 | 产品动作 |
| --- | --- | --- |
| 正常 | 正常兑现或偶发延期。 | 正常使用。 |
| 关注 | 多次延期或超过 72 小时未回应。 | 提醒先处理旧约定。 |
| 受限 | 第一次严重失信。 | 暂停新建高价值契约，先处理当前约定。 |
| 暂停 | 90 天内第二次严重失信。 | 正式契约暂停 14 天，只保留记录/日记/轻任务。 |
| 退出 | 180 天内第三次严重失信或长期拒绝修复。 | 停止正式契约服务，进入封存/退费流程。 |

### 12.2 退费与封存

家长严重失信导致退出时，按未使用会员权益处理退费，已使用服务不退。

记录不因退费而被删除，孩子努力记录可长期保存。

封存文案强调：家长没有履约，不代表孩子的努力没有价值。

测试阶段该机制不做强曝光，但用户协议和后台逻辑需预留。

### 13. 约定修复中心

“争议不是上法庭，而是把一个说不清的约定重新修好。”

产品不是裁判，而是史官、主持人、翻译器和方案生成器。约定修复中心内部可叫争议处理，但前台家长端叫“约定复盘”，孩子端叫“愿望协商”。

| 状态 | 含义 |
| --- | --- |
| 等待回应 | 一方提出修复，另一方尚未回应。 |
| 说明中 | 双方正在提交说明。 |
| 待补充 | 需要补证、补做或补充原因。 |
| 协商中 | 双方正在选择处理方案。 |
| 待确认 | 已有方案，等待确认。 |
| 已修复 | 双方达成一致并完成处理。 |
| 已搁置 | 暂时不继续，但记录保留。 |
| 未达成一致 | 多轮协商后仍无法共同确认。 |
| 已封存 | 不再推进，进入时间胶囊。 |

### 13.1 处理方案

按原契约兑现。

延期兑现。

补证后确认。

补做后继续。

按比例折算。

替代同等级奖励。

暂时搁置。

放弃奖励但保留努力记录。

封存进入时间胶囊。

### 13.2 成果折算

争议期间奖励不一刀切冻结。已完成部分可以先确认，有争议部分暂缓。比如 10 次专注完成 6 次，可折算为 6 个小愿望点或中愿望 60% 进度。

### 14. 见证人系统

“见证人只负责让承诺更稳，不负责替家庭判案。”

见证人不是家庭法官，不默认拥有裁判权。MVP 免费提供 1 个纪念见证人，以帮助用户理解机制和形成轻传播。V1 扩展提醒、协商和有限裁定见证。

| 级别 | 默认状态 | 权限 | 不可做 |
| --- | --- | --- | --- |
| 纪念见证人 | 默认 | 看到契约名称、愿望等级、完成纪念，可送祝福。 | 不看金额、证据、争议、树洞。 |
| 提醒见证人 | 可选 | 看到是否待回应，可温和提醒。 | 不裁定、不公开批评。 |
| 协商见证人 | 双方授权 | 在协商时查看必要摘要并提供建议。 | 不能单方进入、不能修改契约。 |
| 裁定见证人 | 默认关闭 | 仅在签约前明确授权的客观项目中有限裁定。 | 不处理家庭奖励纠纷和情绪争议。 |

另一位父母如果对奖励、预算、时间或执行有实际决定权，应作为共同签署人，而不是见证人。

奖励金额默认不向见证人展示。

老师不进入 MVP 或默认体系。

见证人端首版使用 H5/小程序。

孩子不能一键举报式触发见证人；需先提醒家长，超时再温和提醒见证人。

### 15. 孩子端愿望后院、亲子日记与时光邮局

“孩子端要让孩子感觉：我不是在被管理，我是在用努力养大自己的愿望世界。”

### 15.1 愿望后院

孩子端的核心不是任务列表，而是愿望后院：一个由孩子努力驱动变化的轻放置成长世界。MVP 只做最小版本：当前愿望卡片、愿望番茄钟、猫猫来访、愿望纪念卡。V1 扩展猫猫图鉴、小院装饰、能力徽章、周报和时光邮局。

| 模块 | MVP | V1/V2 |
| --- | --- | --- |
| 愿望卡片 | 显示当前愿望、任务、奖励和进度。 | 支持多愿望、阶段愿望和梦想项目。 |
| 猫猫来访 | 完成首个任务后安静猫来访。 | 按任务类型吸引不同猫猫。 |
| 小院装饰 | 完成后小院变亮。 | 轻装饰、主题皮肤，不做无限养成。 |
| 能力徽章 | MVP 预留。 | 习惯退役后归档为能力。 |
| 努力纪念卡 | 完成小约定后生成一张。 | 愿望纪念页、周报、年报。 |
| 时光邮局 | MVP 预留小纸条。 | 家长写信、孩子写给未来自己、延迟送达。 |

### 15.2 猫猫系统

| 任务类型 | 猫猫 |
| --- | --- |
| 专注学习 | 安静猫、书桌猫 |
| 阅读 | 书页猫、月光猫 |
| 运动 | 风跑猫、跳跳猫 |
| 家务 | 整理猫、扫帚猫 |
| 情绪表达 | 云朵猫、抱抱猫 |
| 长期坚持 | 老朋友猫、守约猫 |
| 能力归档 | 徽章猫、毕业猫 |
| 亲子陪伴 | 双人猫、信箱猫 |

猫猫是努力吸引来的客人，不是抽卡奖品。

不做稀有概率、十连、SSR、限定猫、付费猫、商家联名猫。

可以有轻微不确定感，但不能让孩子为了刷随机结果而无限做低级任务。

### 15.3 防沉迷与轻社交

不做强红点、限时倒计时、断签清零、排行榜。

小院每日互动次数有限，完成后提示孩子去做别的事。

MVP/V1 不做孩子之间社交。V2 可做小院名片、猫猫图鉴、能力徽章分享。

只展示努力世界，不展示奖励金额、家庭隐私、争议记录、学校信息。

### 15.4 亲子日记与时光邮局

每次约定完成生成亲子日记：愿望、任务、努力、复盘、家长回应、猫猫来访。

家长可写给现在的孩子，也可写给未来的孩子。

孩子可写给未来的自己，也可在 AI 辅助下写给家长。

纪念册、时间胶囊、能力档案必须支持导出和长期保存。

### 16. 惊喜奖励与低攀比数据池

### 16.1 惊喜奖励

惊喜奖励可以保留，但不能设计成抽卡、盲盒或诱导消费。小愿望可以轻随机，中愿望以上通过进度累计和双方确认解锁。

| 等级 | 随机规则 |
| --- | --- |
| 小愿望 | 可以轻随机，但价值差异必须小，一天次数有限。 |
| 中愿望 | 通过愿望星星、进度和里程碑解锁，可三选一。 |
| 大愿望 | 不随机，必须走契约确认。 |
| 梦想愿望 | 绝不随机，必须专项立项。 |

不使用抽卡、爆率、稀有、欧皇、十连、保底等语言。

改称愿望进度、星星累计、里程碑奖励、解锁机会。

MVP/V1 不做商家赞助，不做孩子端导购。

惊喜优先非商品化：动画、徽章、留言、选择权、家庭纪念卡。

### 16.2 低攀比奖励灵感库

同龄数据池不是孩子端攀比工具，而是家长端低攀比奖励灵感库。数据池默认关闭，家长主动开启，系统只做大样本、匿名、粗粒度展示。

| 规则 | 要求 |
| --- | --- |
| 展示对象 | 只给家长看，孩子只看到家庭奖池更新。 |
| 数据范围 | 同年龄、同任务类型、同预算边界、区级/城市级大样本。 |
| 不做 | 同校、班级、小区、兴趣班、小样本圈层。 |
| 样本阈值 | 小于 100 个家庭不展示，小于 30 个活跃样本不生成标签。 |
| 展示方式 | 奖励类型、低成本高反馈、陪伴类、自主权类、体验类。 |
| 不展示 | 排名、金额均值、高价愿望榜、品牌热度榜。 |

### 17. 数据、隐私、安全与合规边界

### 17.1 数据分级

| 等级 | 数据类型 | 默认权限 |
| --- | --- | --- |
| A 低敏展示数据 | 愿望非敏感版本、徽章、完成纪念。 | 家庭确认后可分享。 |
| B 契约执行数据 | 任务、番茄钟、进度、验收、兑现状态。 | 孩子、签约家长、共同签署人可见。 |
| C 结果证据数据 | 照片、短语音、文件、运动记录。 | 按任务验收协议可见，最小化采集。 |
| D 孩子个人表达 | 树洞、小纸条、未发送情绪、给未来自己的话。 | 默认只有孩子自己可见。 |
| E 风险保护数据 | 高风险表达、异常争议、多次删除、儿童保护风险。 | 平台安全系统可见，前台不展示。 |

### 17.2 家长查看与删除边界

家长可以查看和导出任务相关数据：原始契约、任务记录、证据、兑现记录、家庭共享日记。

家长不能单方查看孩子树洞、私密日记、未发送情绪和给未来自己的话。

家长不能单方彻底删除孩子个人努力记录、原始契约、约定修复记录、能力档案和时间胶囊。

可以支持隐藏、封存、共同删除、依法删除。

### 17.3 异常情绪与安全风险

| 层级 | 处理 |
| --- | --- |
| 普通情绪 | 不外泄，系统支持孩子整理、保存、转成可分享表达。 |
| 持续异常 | 给家长非泄密式提醒：近期孩子压力信号较高，建议轻松沟通，不展示原文。 |
| 明确安全风险 | 进入人工复核和儿童保护 SOP，最小必要披露。AI 不自动报警。 |

### 18. AI 能力边界与可解释机制

AI 是建议者、拆解者、转译者和提醒者，不是法官、心理咨询师或家长替身。所有关键内容必须由用户确认后发送或生效。

| AI 能力 | 可做 | 不可做 |
| --- | --- | --- |
| 契约生成 | 把愿望拆成任务、证据、兑现时间。 | 自动替双方签约。 |
| 奖励匹配 | 基于家庭奖池给出等级建议和理由。 | 诱导高消费或商家推荐。 |
| 难度评分 | 给出标准模型参考，让家长和孩子调整。 | 替家庭做最终裁决。 |
| 沟通转译 | 把强情绪转成可协商表达。 | 篡改事实或美化失信。 |
| 约定修复 | 整理双方论证，提出补证/延期/折算方案。 | 判定谁胜诉。 |
| 写信润色 | 帮家长真诚表达，帮孩子说清感受。 | 伪造情感、自动发送。 |
| 安全风险 | 识别风险并进入流程。 | 自动报警或向家长泄露树洞原文。 |

### 19. 商业化、会员体系与增长机制

“我们不卖孩子的愿望，不卖家长的焦虑，只卖一个可信的家庭契约系统。”

### 19.1 订阅制原则

只从用户侧收费，不从商家侧收费。

不做商品抽佣、活动票务分成、品牌赞助、商家奖励池、孩子端导购。

商品、活动和机构内容最多作为非商业化灵感，不成为推荐变现来源。

会员费是家长购买产品服务；奖励是家庭内部承诺，二者必须分开。

### 19.2 会员分层

| 版本 | 功能边界 | 定位 |
| --- | --- | --- |
| 免费版 | 1 家长 + 1 孩子；3 个小约定；基础番茄钟；基础愿望后院；30 天记录；1 个免费见证人；基础亲子日记。 | 跑通首个闭环，让家庭理解价值。 |
| 家庭会员 | 不限小约定；中/大愿望；多家长；多孩子；长期云记录；完整日记；基础 AI；导出；时间胶囊基础版。 | 日常家庭契约闭环。 |
| 家庭 Pro | 高级 AI 愿望拆解、目标奖励匹配、约定修复、能力归档、高级报告、多见证人角色、时光邮局、年度报告、多皮肤。 | 长期成长档案和高级家庭系统。 |

### 19.3 增长机制

孩子推动家长安装：孩子希望愿望被认真记录。

家长口碑传播：少催促、少扯皮、奖励不乱给。

见证人轻传播：爷爷奶奶、亲友通过 H5 接触产品。

成长报告传播：分享努力世界和纪念卡，而不是奖励金额。

孩子端传播：V2 以后只分享小院名片、猫猫图鉴、能力徽章。

### 20. MVP 完整需求

“MVP 不做完整平台，只做一个极致清晰的小闭环。”

### 20.1 MVP 用户流程

家长打开 App，看见主标题“把随口承诺，变成孩子相信的家庭约定”。

家长注册并创建家庭。

家长完成 5 条家庭契约原则确认。

系统推荐首个小约定：25 分钟愿望番茄钟。

家长邀请孩子进入孩子端。

孩子选择小愿望，确认任务，点击开始守约。

孩子完成番茄钟，提交一句复盘，可选照片。

家长收到“孩子已完成约定，进入兑现阶段”。

家长选择已兑现 / 延期 / 待复盘。

系统生成亲子日记，愿望后院出现安静猫来访。

### 23. 指标体系与灰度测试方案

### 23.1 MVP 核心指标

| 指标 | 定义 | 判断意义 |
| --- | --- | --- |
| 首次设置完成率 | 家长完成原则确认和奖池初始化比例。 | 验证 onboarding 是否过重。 |
| 首个小约定创建率 | 完成设置后创建首个约定比例。 | 验证家长是否理解价值。 |
| 孩子开始守约率 | 孩子确认愿望后点击开始比例。 | 验证孩子端参与感。 |
| 首个约定完成率 | 任务完成并提交复盘比例。 | 验证任务设计是否合理。 |
| 家长回应率 | 孩子达成后家长选择兑现/延期/复盘比例。 | 验证履约提醒有效性。 |
| 亲子日记生成率 | 约定完成后生成日记比例。 | 验证情感闭环。 |
| 第二个约定创建率 | 家庭创建第二个约定比例。 | 最关键，验证不是新鲜感。 |
| 7 日家庭留存率 | 家庭 7 日内仍有至少一次有效行为。 | 验证短期留存。 |

### 23.2 灰度测试建议

第一轮：10-20 组熟人家庭，观察首个闭环是否能跑通。

第二轮：50-100 组 8-12 岁家庭，验证第二个约定创建率和家长回应率。

第三轮：付费测试，验证家庭会员转化、免费见证人是否提升传播。

访谈重点：家长是否觉得被审判，孩子是否觉得被管理，是否愿意继续使用。

### 24. 风险矩阵与应对方案

| 风险 | 触发机制 | 应对 |
| --- | --- | --- |
| 家长觉得被审判 | 履约记录、见证人提醒过重。 | 外部表达改为承诺提醒、家庭协作，MVP 不突出失信惩罚。 |
| 孩子觉得被管理 | 孩子端像任务列表或强锁工具。 | 愿望后院、主动开始、猫猫来访、不做强锁。 |
| 奖励依赖 | 所有行为都价格化。 | 不可建模清单、任务分类、积分衰减、能力归档。 |
| 证据争议 | 照片真假、质量标准不明。 | 事前验收协议、补证/补做、约定修复。 |
| 见证人制造冲突 | 见证人越界、亲戚审判。 | 默认纪念见证，不看隐私，不裁决。 |
| 隐私泄露 | 树洞外泄、证据过度采集。 | 数据分级、默认私密、非泄密提醒。 |
| 同龄数据攀比 | 孩子看到别人愿望。 | 只给家长看，低攀比灵感，大样本阈值。 |
| 商业信任破坏 | 商家推荐或导购。 | 只做订阅，不从商家收费。 |
| MVP 过重 | 功能一次性铺开。 | 只跑小约定闭环，其他后置。 |
| 合规不确定 | 未成年人数据和安全风险。 | 上线前法务审核、最小化、可退出、可导出。 |

### 29. 通知与状态规则矩阵

通知必须服务于协作，不制造压迫。孩子端不应接收“父母失信”式刺激文案；家长端不应接收“你被孩子投诉”式审判文案。

| 触发 | 接收方 | 默认文案方向 | 频率限制 |
| --- | --- | --- | --- |
| 契约待确认 | 家长/孩子 | 有一个新的家庭约定等待你确认。 | 即时 + 24 小时一次提醒 |
| 任务开始 | 孩子 | 准备好了吗？开始为愿望充能。 | 仅孩子主动进入 |
| 任务完成 | 家长 | 孩子已完成约定，进入兑现阶段。 | 即时 |
| 家长未回应 24h | 家长 | 这个约定还在等待你的回应。 | 每日最多一次 |
| 家长未回应 72h | 家长 | 继续等待可能降低孩子对约定的信任。 | 每日最多一次 |
| 延期到期 | 家长 | 你设置的兑现时间到了。 | 即时 + 次日一次 |
| 见证人提醒触发 | 见证人 | 这个家庭约定正在等待回应，你可以温和提醒。 | 仅授权后触发 |
| 孩子持续异常 | 家长 | 近期孩子在多个约定中出现较高压力信号，建议轻松沟通。 | 低频，不展示原文 |
| 约定完成 | 孩子/家长 | 这次努力已进入亲子日记。 | 即时 |

### 30. 不可建模清单与安全规则

### 30.1 不可作为奖励或惩罚条件的事项

食物、水、睡眠、医疗、药物、衣物、安全住所、基本照顾。

人格尊严、被尊重、被倾听、被拥抱、免于羞辱、免于威胁。

上学、基本安全、健康检查、必要社交和休息娱乐。

不受体罚、不被赶出家门、不被剥夺基本通信与求助。

涉及身体羞辱、人格羞辱、公开羞辱、家庭成员对立的任务或惩罚。

### 30.2 高风险表达拦截

| 风险类型 | 示例 | 系统处理 |
| --- | --- | --- |
| 基础照顾条件化 | 考不到多少分就不给饭/不给睡。 | 拦截建模，提示基础照顾不可交易。 |
| 身体伤害 | 做不到就打/罚站到深夜。 | 拒绝生成，进入风险提示。 |
| 羞辱与公开惩罚 | 失败就发到群里让大家笑。 | 拒绝生成，提示不支持羞辱性规则。 |
| 情感剥夺 | 不完成就不爱你/不理你。 | 拒绝生成，提供替代表达。 |
| 高压监控 | 全程开摄像头盯着。 | 不支持，建议轻证据。 |
| 危险奖励 | 未成年人不适合的产品或活动。 | 标记风险，需家长重新选择。 |

### 34. 产品评审清单

| 评审维度 | 问题 |
| --- | --- |
| 价值判断 | 家长 30 秒内能否理解：它不是番茄钟，而是家庭约定闭环？ |
| 孩子体验 | 孩子是否觉得这是我的愿望后院，而不是爸妈的任务表？ |
| MVP 克制 | 首版是否只验证首个小约定，没有把 V1/V2 功能塞进来？ |
| 契约清晰 | 每个任务是否都提前写清目标、奖励、证据、兑现时间？ |
| 家长压力 | 履约提醒是否温和，不像审判？ |
| 孩子信任 | 树洞和小纸条是否默认私密？ |
| 商业边界 | 是否完全没有孩子端导购、商家赞助、商品抽佣？ |
| 合规边界 | 是否没有学校、机构、视频、同校数据池、资金托管？ |
| 长期价值 | 完成后是否生成了亲子日记和可保存记忆？ |
| 数据安全 | 谁能查看、导出、删除、封存是否清楚？ |
