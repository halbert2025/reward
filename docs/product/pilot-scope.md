# Reward 测试用户版本范围

日期：2026-05-25  
阶段：Alpha / Pilot Readiness  
状态：范围冻结草案

## 1. 阶段目标

测试用户版本的目标不是扩展更多玩法，而是把已通过内部验收的 MVP 主闭环改造成少量真实测试家庭可以安全试用的版本。

本阶段优先补齐真实家长登录、家庭创建、儿童邀请码、witness 邀请链接、线上数据库、告知与同意、退出/导出/删除/封存请求、最小人工处理流程、部署、监控和回滚。

## 2. 支持平台

第一批测试用户版本仅支持桌面 Web 和移动浏览器基础适配。PWA 可作为后续增强，不作为第一批阻塞项。

不支持原生 iOS App、原生 Android App、小程序、桌面客户端。

## 3. 支持角色

### Parent

测试用户版本必须支持家长注册或登录、创建家庭、确认试点告知与同意、邀请 child、创建小约定、查看孩子提交的复盘、做出兑现/延期/待复盘回应、查看家庭日记、发起退出/导出/删除/封存请求。

### Child

测试用户版本必须支持孩子使用家庭邀请码加入、使用昵称或轻量身份进入自己的家庭、确认小约定、使用猫猫番茄钟、提交一句复盘、写 ChildNote、看到儿童友好的隐私提示。

Child 不要求绑定邮箱、绑定手机号、进行开放社交或接收营销内容。

### Witness

测试用户版本必须支持 witness 通过家长生成的链接访问安全摘要，但看不到 ChildNote、证据、金额、修复争议详情。

### Admin / Operator

测试用户版本至少需要内部人工处理能力：查看测试家庭列表、查看同意状态、查看数据请求、标记人工处理进度、记录处理结果。

## 4. 最小用户闭环

1. 家长注册或登录。
2. 家长确认试点告知与同意。
3. 家长创建家庭。
4. 家长生成儿童邀请码。
5. 孩子通过邀请码加入家庭。
6. 家长创建小约定。
7. 孩子确认约定。
8. 孩子启动猫猫番茄钟。
9. 孩子完成后提交一句复盘。
10. 家长选择兑现、延期或待复盘。
11. 系统生成家庭日记。
12. 家长可发起退出、导出、删除或封存请求。

## 5. 数据范围

第一批测试用户版本允许收集家庭基本信息、家长登录标识、孩子昵称、家庭成员角色、合约版本与状态、任务状态、一句复盘、家长回应、家庭日记、ChildNote、审计日志、试点同意记录、数据处理请求记录。

第一批测试用户版本默认不收集孩子真实姓名、孩子学校、孩子班级、孩子手机号、孩子邮箱、精确地理位置、通讯录、视频、真实支付信息、第三方社交账号。

## 6. 证据策略

第一批测试用户版本建议继续采用 mock/文字说明策略：不上传真实照片，只记录可选文字说明，页面明确提示“当前测试版不上传照片”，并保留未来 StorageAdapter 设计。

如果改为真实上传，必须先完成证据照片规则、EXIF 清理、文件删除和封存流程、敏感内容提示、人工处理流程。

## 7. AI/Kimi 策略

第一批测试用户版本默认使用 `AI_PROVIDER_MODE=mock` 或 `AI_PROVIDER_MODE=template`，不把 ChildNote 原文或证据照片发送给外部模型，不让 AI 做裁判，不让 AI 自动通知家庭成员。

真实 Kimi 接入必须另行验收：脱敏、可关闭、失败降级、日志最小化、家长额外知情。

## 8. 成功标准

第一批测试用户版本可发出测试邀请的最低标准：

- P0/P1/P2 阶段验收通过。
- 家长、孩子、witness 权限负向测试通过。
- 主链路 E2E 通过。
- 试点告知与同意入口可用。
- 数据请求入口可用。
- 部署和回滚文档完成。
- Before Pilot Gate 中的真实试点阻塞项已关闭或明确限制为内部测试。
